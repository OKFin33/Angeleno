# Angeleno 首版 Spec

2026-10-31 · 沿用已确认首版设计，按 Owner 当日明确选择加入主动网页发现；变更依据见本节末。设计确认不代表功能已实现或语音体验已通过；实际状态见 [baseline](baseline.md)，工作与实施顺序见 [Issue #1](https://github.com/OKFin33/Angeleno/issues/1)。产品目标见 [Intent](intent.md)。

## 1. 产品承诺与范围

Angeleno 是围绕 LA 当地生活设计的实时语音 Agent，首个人物为 Jo。用户通过实时语音与有地方背景、偏好和限度的人物交流；涉及当下信息时，Jo 能主动搜索新资料、打开网页阅读证据，再接回谈话。

主要体验是通过 Jo 了解当地生活，具体出行推荐与查证为辅，无须用户已在 LA。首版中文主用，地名保留自然英文表达。不要求每段交流产出推荐、行程或漂亮观点，也不把极细语感全面达到理想朋友水平作为交付前置。

| 范围 | 首版约定 |
| --- | --- |
| 核心地方内容 | Jefferson Park 与 USC／Exposition Park 周边；街区日常、建筑、艺术文化去处 |
| 其他生活节点 | 保留 Culver City 工作背景、Sherman Oaks 成长背景，先补少量必要资料 |
| 交流入口 | 浏览器实时语音；文字入口用于同一核心的调试与评测 |
| 信息能力 | 整理好的地方资料＋DeepSeek 官方 Search 发现新来源、Fetch 阅读网页；按谈话目的自主选择 |
| 人物与连续性 | 沿用 Jo、既定朋友起点和独立试用记忆，跨通话延续真实交流 |
| 展示 | 通话为主，查询后有简短查证卡片及可展开来源 |
| 暂不承担 | 全 LA 深度覆盖、实时人流保证、社交账号访问、完整行程规划、预订交易、导航、通话外主动活动、多角色平台、英文主用版本 |

覆盖范围约束资料准备和评测深度，不限制用户话题。Jo 可以聊别处或日常其他事情，承认不熟悉；核心区域内同样不承诺全知。

本版以地方生活交流与受控查证形成具体能力；人物连续性、自然承接、私人状态保护和语音交付共同构成体验底线。

## 2. 使用情景与人物表现

### 核心使用过程

1. 用户打开通话页，看到 Angeleno、人物 Jo 和服务状态；可开始、静音和挂断。页面用简短说明交代这是虚构人物，以及首版熟悉区域；不让用户先读人物小传或教她扮演。
2. 从既定朋友起点交流，不虚构两人共同过去。用户可以随口聊街区、人物偏好、生活或其他话题。
3. 稳定资料足以支持的问题自然回答；可变信息或影响实际安排的现实结论需要核实。查询无需逐次征求许可，但必须服从来源与调用上限。
4. 查询时简短说明，再等待结果；用户可补充条件、取消、转题或挂断。收到仍适用的结果后正常回答，并在页面留卡片。
5. 同一试用身份重拨可接续已发生的交流。过去查过的事实保留时间性质，不自动变成现在仍成立的结论。

以下是合成的设计场景，不是唯一正确台词或模型输出：

| 输入或变化 | 应得到的体验 |
| --- | --- |
| “你住的那一片，有没有游客容易忽略、但你挺喜欢的地方？” | 有具体地方和人物关注，不像批量导览；可以聊深、简答或转题，不强行安排出行 |
| “那里有什么吸引你？” | 从人物视角谈理由，不为了体现地方能力每轮联网或引用资料 |
| “周六下午能去吗？” | 弄清所指地点和日期；搜索或打开适用来源，区分常态与临时例外 |
| “我是说下周，不是这周。” | 保留原话与纠正，按新日期处理，旧条件结果失效 |
| “算了，先聊点别的。” | 接新话题，旧查询结果不再抢话或覆盖当前卡片 |
| “你上次说那个地方……” | 能接续实际说过的内容；涉及现在的营业或活动则重新核对 |

### 人物、语言和事实边界

人物使用显式指定、来源和分发范围清楚的作者包。Jo 的固定身份、既定朋友起点和作者保护继续有效；兼容创作遵守作者边界。当前尚未收入可分享的 Jo 作者包，离线合成角色不能替代产品人物验收。新增检索不改写人物种子，不以填资料为由修改旧记忆。

中文是呈现语言，不新增学习中文的身世。允许正常英文地名和短语；识别到的中英文别称映射到同一地点。地名歧义影响结论时先作一次简短澄清，不静默猜另一个场所；短暂英文输入可理解后继续中文回答，完整英文体验不列为本轮保证。

人物通过注意、取舍、偏好和局限体现，不能靠密集背景自报、LA 口头禅或每轮讲故事替代。预设用户知道 Jo 是虚构 Agent，人物经历以逻辑合理为准：与作者材料、已说过的话及地方现实相容，不需要“真实发生过”。生活圈内稳定存在的地点可以有符合人物的日常经历，记忆中标为人物虚构；检索结果不赋予亲历，有时效的展览、活动不能说成自己去过；角色发挥不成为真实用户经历或共同约定。原稿的虚构画框店等只能作为人物设定，不能被放进真实可前往地点清单。

## 3. 地方内容、来源与时效

### 四类信息

| 信息 | 权威来源与用途 | 不得推导成什么 |
| --- | --- | --- |
| 人物材料 | 作者包；身份、关系、偏好及可创作背景 | 商户登记、现实活动事实、用户共同过去 |
| 地方资料 | 有来源的 Markdown 条目；稳定地理、建筑、机构与地方背景 | 默认当前营业、人物亲历 |
| 当下查证 | 实际搜索／阅读针对当前问题返回的证据；带核对时间与适用日期 | 永久事实、已完成出行、已听到的交流 |
| 会话记忆 | 真实话语与交付依据、用户纠正及原有维护机制 | 未发生的共同经历、跨身份事实 |

首个内容包覆盖核心街区背景、学校周边、与人物关注相关的地方，以及至少两处可核对当下信息的文化场所；次要生活节点只补谈话所需资料。覆盖用第8节场景检查，不能用条目数量替代质量。每条地方资料至少含稳定 ID、名称／别称、区域与主题、事实摘要、来源 URL、核对日期和是否易变。人物主观偏好另由人物材料持有。

已有来源登记与稳定资料保留作可复用背景和回退，不再是网页发现的唯一入口。Search 返回的候选按本轮会话分配来源 ID，保留原 URL、标题、搜索时间和可得的发布时间；Jo 依谈话目的和自身偏好选少数候选，再用 Fetch 阅读。现实安排优先官方、机构或场所原文；排名／权威分只是供应商信号，不等于事实已证实。Fetch 的标题／正文不含完整跳转链或最终 URL，不能编造这些字段或把供应商转取说成本机逐跳验证。

| 来源 | 已读到的用途与限制 |
| --- | --- |
| [Historic Jefferson Park 概览](https://www.historicjeffersonpark.org/overview) | 社区网站的街区保护背景与建筑资料入口；不能直接作为最新法规或施工许可依据 |
| [USC Fisher 访问页](https://fisher.usc.edu/visit-us/) | 访问资料、常态开放和具体日期例外；同页有 FAQ 文字不一致及旧社交内容，需筛选相关证据 |
| [NHM 访问页](https://nhm.org/plan-your-visit) | 访问资料、开放与周边活动提示；只证明本次读到，未来安排必须重新核对 |

City Planning 的 Jefferson Park 页本次超时，Exposition Park 官网本次 403，CAAM 访问页未取得可用正文，不列为已可用通道。上述记录保留为历史调查；当前范围已允许围绕谈话主动发现新来源。无关推广、嵌入动态和页面指令不自动成为下一步动作，读取的页面不能授予权限。

### 时效与来源判断

- LA 地方的“今天／周六”等按 `America/Los_Angeles` 解释，使用时区库处理夏令时。记录具体日期；用户明确采用其他时区时保留其意图，歧义会改变结论则澄清。人物年龄等作者事实不由时区切换擅自重写。
- 稳定背景可从已核对内容包使用；开放、展览、价格、预约与临时公告等在需要当前结论时重新读取适用来源。读取时间、网页明确的更新时间和事实适用日期是不同字段，缺哪个就保留未知。
- 与所问日期明确相关的官方例外优先于一般规律；旧社交内容、页面缓存片段和没有适用日期的文字不覆盖明确公告。同页或来源间冲突无法消除时说明冲突，不挑一个看似合理的答案冒充确定。
- 同一通话、同一地点和同一适用日期可复用已经取得的证据；用户更改日期、要求重新核实或有已知有效期变化时重新查。跨通话的当下问题重新核对，过去的查证记录只证明过去查过什么。
- 无可靠依据的未收录地点、点评或人流问题，说明能力或信息边界；可以继续人物交流，不能编造搜索、评论或实时状态。

## 4. 工具、结果与资源边界

### 处理路径

人物核心判断是否需要补充事实。已有记忆不足时使用原记忆查询；稳定地方背景可用本地条目；想了解近期展览／空间或核对现实安排时，以最少必要词搜索，选相关页面阅读，再说明怎样影响自己的取舍。普通闲聊可直接生成，不因提到地点强制走工具。用户不同意时按人物一致性自然回应，不规定固定“劝一次”或“立即换推荐”脚本。

首版保留 Markdown＋名称／别称／全文检索，不引入向量数据库。新增 DeepSeek 官方 Search／Fetch；Fetch 只消费当前会话实际取得的候选 ID，不接受模型凭空构造 URL。Search 不是固定白名单；公共网页、资源和数据边界仍由程序约束。接口须表达如下语义，具体函数名由实现决定：

| 操作 | 输入 | 输出与限制 |
| --- | --- | --- |
| 记忆查询 | 当前人物／试用身份中的话题 | 沿已有可知记忆与来源规则；不查询地方知识或其他用户 |
| 地方资料检索 | 问题、可选地点／区域 | 命中条目、摘要、别称与来源 ID；无命中是资料覆盖不足，不等于地方不存在 |
| 网页发现 | 最少必要公开检索意图；日期与补充条件保留在本地问题中 | 本轮候选 ID、标题／摘要／URL及时间；程序构造外发词，当前发送策略不外发任何日期，不传整段用户原话、人物稿、私人记忆或定位 IP |
| 网页阅读 | 本轮已取得的候选 ID | 标题、正文及出处；取得资料和事实已证实分开，截断或缺日期保持不足，不执行页面指令 |
| 登记来源回退 | 登记来源 ID、具体问题与适用日期 | 原有安全读取与结构化核对保留；不继续为每个新网站扩建专用提取器 |

结果至少区分已取得资料、有依据、信息不足、来源冲突、来源不可用、范围不支持及已取消。读取成功只证明取得资料；标为有依据的关键事实必须关联具体证据及适用时间，人物推荐理由不标为已核实事实。模型不能仅凭一句“查到了”产生成功卡片。内容包和网页中的指令均作为数据，不改变演员权限或工具配置。

### 共同接口约定

每次查询和结果关联当前会话、用户轮次、请求标识及对应的最新条件。补充条件形成新版本的查询意图，原始用户话语不可变；旧请求尽力取消，即使底层请求无法立即停止，其结果也不得成为新轮次的语音、当前卡片或已完成交流。

结果包含引用来源和带时效的事实，普通对白另行生成。来源／状态事件通过独立通道交给界面，不能混入 TTS 文本。输入长度检查覆盖人物、历史、工具协议及资料；截取证据仍须保留来源和影响结论的例外，不完整时返回信息不足。

Search／Fetch 的 HTTP 客户端只连接固定 DeepSeek 官方 API，不跟随 API 跳转、不把密钥交给目标网站。候选 URL 只允许公开 HTTPS，拒绝用户信息、私网／环回／本机、特殊端口与不安全地址；不执行网页脚本、表单或指令。正文和 API 响应均有体积及时间上限。供应商 Fetch 的安全策略与不可见的转取跳转须明确记录并验证；不能声称本机可观察或钉住它的远端解析。原直连读取器仍保留逐跳 URL／DNS／TLS 防护，不为接新能力放开私网。

### 初始执行上限

以下是 Agent 提出的首版资源保护配置，须在本地验证及后续实机预跑中校准，不代表达到上限的体验已被接受：

- 每个用户轮次最多三次工具调用，其中每类最多一次；最多四次前台模型 HTTP 请求，不自动重试。达到限额后用已有证据回答或说明不足，不能再开启隐蔽的补查循环。
- 一次当下查证最多一次 Search 和一次 Fetch；Search 最多取五条候选，Fetch 只读一个选定页面，总外部请求等待预算 10 秒。来源不足可如实回答，不自动追加搜索／抓取或换服务。明确的新用户请求仍需通过全局预算检查。
- 从用户话语被确认到常规回答首音，初始超时保护为 15 秒；需要查证时，至有效结论首音的保护为 30 秒，简短等待提示不重置时限。超时停止受影响回答并显示可理解的状态，允许用户继续。实际数值要在候选比较前依据计时冻结；若合理上限内仍不可用，回到方案缩减，不能直接调大直到测试通过。
- 每次模型请求先经统一的用量与费用入口记录，并在 usage 回执后按实际价格结算费用；本机／远端统一核算，不同时使用多份账本各自计费。actor、工具续接、维护、失败尝试均计入。ASR 独立计时。账户余额触及止损线是明确停止条件，不能靠换账本、模型或子模块绕开。

首版采用 DeepSeek 官方 Search／Fetch，产品选择与实际收费授权分开。模型按 usage、Search／Fetch按有结果请求计费，共用原账户账本、余额止损及未知费用预留，不另开可重置预算。每批和每请求边界检查有效许可；失败、取消与未知结果保留记录，ASR 独立核算。账户金额、运行暂停和授权由操作者私有记录持有，不写入产品设计或 Git。没有可核对授权时只进行离线验证；新仓或新账本不产生新额度。

## 5. 实时语音、页面与失败行为

### 查询等待与打断

开始查证时自然、简短说明一次，随后等待；不持续说话填空，不同时维持另一段闲聊再插入旧结果。页面显示正在核对的对象，用户仍能说话、静音或挂断。

| 事件 | 必须发生的行为 |
| --- | --- |
| 返回仍适用的结果 | 针对原问题给简洁结论，允许自然继续；卡片与该回答关联 |
| 用户补充条件 | 保留原话及补充，按最新意图处理；旧条件结果不覆盖新条件 |
| 明确取消或换题 | 停止旧任务的后续使用，接新话题；不在稍后突然补播旧结果 |
| 用户打断正在播放的回答 | 停止旧音频；保存已有交付依据，未确认部分不当作用户已听到 |
| 用户挂断或断线 | 清理媒体与不再需要的生成／查询，失效迟到回调；重拨不续播旧队列 |
| 来源无内容、超时或冲突 | 说明可确定与不可确定的部分，可继续通话；预期查询失败不触发整通电话退出 |
| actor／媒体链路不能继续 | 明确本轮失败，停止重复生成／播放，给出重新拨号入口；不无限重连 |

识别错地点时允许用户口头纠正；无法唯一匹配时作一次短澄清，不通过模型猜测补出查询目标。补充条件和换题由对话判断，取消及过期检查必须在工具返回、后续生成和发送界面事件前共同执行。

### 查证卡片

页面保留通话状态、开始／挂断、静音及既有字幕能力。外部查询产生卡片：地点或问题、已有依据、适用日期（相关时）、读取时间与结果状态；展开可查看来源名称、链接及必要的冲突说明。搜索摘要／Fetch正文只标“已取得资料”，不自动产生已核实结论；普通闲聊不生成卡片。

先显示当前查询状态，结果有效时原位更新，保持一张当前卡片；不把页面发展成搜索结果列表或新聊天应用。新查询取代旧卡片，结束通话后最后一张可留到用户离开或再次拨号，重拨清空页面展示。页面卡片不作为长期记忆管理入口。

取消后卡片可显示已取消，不展示迟到结论；已经有效展示过的结果遇到后续转题，不自行变成新话题结论。语音未完整播放时，卡片也不能触发“用户已知／听过”的记忆认定。来源链接只从本轮实际结果绑定或既有登记值输出，页面文本转义，不渲染来源提供的可执行 HTML。

### 延迟证据

分别记录用户话语结束、识别确认、首个有意义音频、查询开始／结束、结论首音、插话与音频停止时间。查询提示音不能代替结论延迟，字幕出现也不能代替实际出声。报告样本数、分布与超时情况；少量样本不能宣称稳定百分位。

已有一次合成输入到出声只证明链路曾连通，不足以确定体验门槛。候选比较前校准第4节保护参数；Owner 的整体通话判断仍是接受条件。

## 6. 记忆、隐私与连续性

新建或接续本轮独立试用身份，保留当前 seed 兼容检查和库占用保护；不迁移旧私人试聊、不清空旧库、不自动更换身份。文字与电话消费同一人物核心和该身份的记忆。

- 用户偏好、真实话语、纠正与已有交流沿现有维护机制保存，并保留来源。一次询问不自动等于永久偏好或已执行计划。
- 查证证据保存在独立于人物长期记忆的结果记录中，带问题、来源、核对时间、适用时间和状态。通话内缓存不得静默更新成“现在仍成立”；会话记忆可知道曾讨论该地，但新当下问题按第3节重查。
- 卡片展示、模型生成、音频交付和用户实际注意力分别处理。只用适配器可取得的交付证据结算交流；缺证据时标记中断或不确定，不将整段生成全文写成已说完。
- 用户要求不保存时沿既有临时交流路径处理，同时不持久保存本轮查证记录和界面历史。原有本地查看／清理路径需覆盖新增记录，不另建网页记忆后台。
- 后台维护不挡住普通接话；维护失败保留原话与旧有效状态。记录保存成功不证明内容语义正确。
- 搜索只发最少必要查询词；不自动附带用户原问题、定位 IP、整段私人聊天、用户身份、私人记忆或作者稿。Fetch 只发实际选定的公开 URL；给演员模型的内容仍服从既有数据与费用边界。对不可分离的私人内容先不搜索，不用外部搜索回显来测试秘密。
- 私聊、数据库、原始日志、密钥和声音原件不进入 Git 或公开 Demo。仅用获准的合成／脱敏样例展示，公开声音素材另按权利与授权处理。

## 7. 架构、接续与技术验证

| 部分 | 责任 |
| --- | --- |
| 人物与会话核心 | 人物材料、上下文、有效记忆、actor 与工具循环、请求预算、轮次和交付结算 |
| Angeleno 内容与查证 | Markdown 内容包、地点别称、Search／Fetch 只读发现与证据、时效与冲突、既有登记来源回退 |
| 音频适配 | 麦克风、识别、TTS、播放、插话与媒体事件；不另维护一套人物历史 |
| 通话页面 | 通话控制、等待／失败状态、字幕与卡片；不自行推定模型事实或语音交付 |
| 评测入口 | 通过同一核心运行固定情景，保存条件与可分享证据，隔离评测记忆 |

首版沿共用核心扩展工具与结果事件，不建立第二套演员或复制记忆系统。Markdown 和登记来源保留可审查的基础；新增搜索发现和阅读共用现有工具循环、取消／改口／迟到隔离、15／30秒保护与交付记忆。不开第二套演员或费用账本。

### 已有实现与缺口

新仓已接入的代码与实测结果由 [baseline](baseline.md) 持有，不能从设计文档推定实现状态。以下是接续时必须处理的接口缺口：

| 既有核心边界 | 新实现需处理 |
| --- | --- |
| 每次只允许一个未结算轮次 | 补充条件按新输入修订意图，先结算旧轮次；原始话语不可覆写 |
| 原工具只有记忆查询 | 接入有界地方检索／查证循环，所有续接计费 |
| 核心流只接受对白字符串 | 增加独立来源与状态事件，防止进入 TTS |
| 媒体适配负责生成、播放与取消的接合 | 预期来源失败允许继续交流，真正媒体错误明确停止 |
| 界面与通话代次关联 | 卡片同样隔离迟到事件，不能写入新通话 |
| 人物运行日期已使用 LA 时区 | 新增地方查证继续沿 LA 日期语义，不改人物固定事实或用户明确时间 |

### 进入 Plan 后的验证条件

1. 本地可立即安排内容包、来源注册、只读抓取、工具循环、页面与记忆契约的实现和离线验证；实施须依据最终确认后的本 Spec。
2. 研究工具可读不等于产品抓取器可用。选定来源须取得正文、日期／例外与错误状态的实际读取证据，未通过的来源禁用或换经核实的同范围来源。
3. 真实正常播完、插话、补充条件、转题、挂断重拨及回退须在获准运行的实际音频环境验证。设备或运行权限不可用时，只暂停依赖该环境的验证，不能把离线事件模拟当成实机证据。
4. 语音预跑同时校准网络／响应超时与实际延迟，冻结候选及比较条件；无法满足可用性时回到缩减或修复，不以文档和单次出声代替通过。
5. 新增服务、收费供应商、预算扩大、主线合并与公开发布均不由本设计自动授权。保留已有运行记录，按最新授权及各账户实际回执核算；新建物理账本不能重置历史用量或扩大权限。

## 8. 评测、接受与交付

### 决策与比较

评测回答：Angeleno 是否像向一个来自 LA 的朋友打听当地，而不像直接问一个语音助手；完整候选能否供 Owner 试用和展示。比较只对同料助手：同一核心的文字入口、同一模型、地方资料、工具与调用上限，只将 Jo 的人物材料换成普通语音助手设定。这样差别集中在“朋友还是助手”，而非信息多少。同料助手是受控对照，不是 ChatGPT；本轮不跑 ChatGPT 参照，交付材料不作与 ChatGPT 或其他同类产品的优劣结论。文字比较避免 ASR 噪声干扰；真实语音用于生命周期、识别／轮次切分／附和、实际播放与延迟验证及 Owner 试用。

角色配置是这项替换的一部分：`character`沿原Jo人物阅读／虚构延续，`assistant`使用普通语音助手身份，不再继承“扮演原创人物”的指令。两臂仍用同一ConversationRuntime、模型参数、工具协议、检索资料／快照、时间、记忆机制与预算；助手也能自然接话、提出有理由的选择和记住已交付交流，不能刻意要求它机械列清单或忘记用户。声明为grounding的完整事实材料原样共享；混在人物文档中的现实信息须在冻结材料时核对，两臂信息不等不能因配置可运行便视为解决。原Jo稿不改写，不静默迁移原记忆。此为既定同料目标的实施澄清，不是降低验收。

实现入口为 `AuthorPack.role`（旧manifest默认character；显式assistant才切换）。`assistant_control_pack(jo_pack)`生成独立助手身份，替换角色材料并原样保留所有声明为grounding的文档；它不猜测抽取混合人物稿中的事实。默认Jo提示和seed保持，换角色不能复用原身份记忆。运行前冻结两份角色配置指纹、同一地方包／搜索语料与共享事实清单；角色差异属于对照处理，工具能力说明共用。当前离线回归只证明配置／数据接线，不是普通助手已获Owner认可或成对实模比较已运行。

按既有七步骨架完成：明确决策与成功标准、推导用例、选样与划分、判分校准、公平比较、交付判断；本轮不做最后的线上监控，两轮试用中核实的失败转为回归例。代码测试、模型输出、真实语音和 Owner 接受各自记录。

### 朋友感的观察特征

| 特征 | 像朋友 | 像助手 |
| --- | --- | --- |
| 有立场的取舍 | 会挑、会说不推荐，理由来自她的口味 | 平衡、齐全的清单 |
| 从生活出发 | 住在那一片怎样、本地人怎么用这个地方 | 百科式介绍 |
| 知道你是谁 | 按你说过的偏好回答，跨通话接上 | 每次从零回答 |
| 说话方式 | 短、口语、会反问 | 结构化陈述、列点 |
| 熟悉边界 | 能说“那边我不太熟” | 均匀覆盖、全知口吻 |
| 要紧的事去核 | 开放时间等影响安排的事查了再说 | 同样查证，作为底线对照 |

允许 Angeleno 比助手更不全面、更有偏好；关键事实不能更差。人物经历按第2节以逻辑合理判断，不以“真实”评分。

### 最小场景覆盖

| 编号 | 情景与观察机会 | 核心判断 |
| --- | --- | --- |
| E1 | 核心街区闲聊、追问偏好，再转向其他日常话题 | 有人物视角、地方具体性和自然承接，不强行推荐／联网 |
| E2 | 稳定地方问题、地名别称或歧义、纠正，并由近期小展问题触发新来源发现 | 人物偏好影响查询与候选选择，所指地点正确，必要时澄清；不把检索结果当作亲历 |
| E3 | 某日期开放／活动，普通规律与临时例外相冲突 | 使用相关来源与 LA 日期，结论和卡片均可追溯 |
| E4 | 未收录小店、不熟悉地方、点评或实时人流 | 可围绕目的搜索发现，不把“未预登记”当永久盲区；无足够证据仍承认未知，不虚构实时人流或亲历 |
| E5 | 来源空白、超时、同页冲突或工具限额 | 结论保留不确定性，失败可继续交流，不无限重试 |
| E6 | 查询中补充条件、取消或换题，旧结果迟到 | 最新条件有效，旧结果不播、不覆盖卡片、不写成已完成交流 |
| E7 | 播放中插话／挂断后重拨，包含未播完结果 | 无旧音频复播，记忆区分已交付与不确定；跨通话当下事实重新查 |
| E8 | 人物虚构地点、过去查证与用户偏好纠正混合 | 虚构／现实／用户事实不混写，纠正生效，无错误共同经历 |

另从“会问一个 LA 朋友什么”推出完整交谈情景：周末去哪或几处哪个值得去、住那边什么感觉、某天能不能去、“你觉得 X 怎么样”（她可以不同意）、她不熟的地方、“上次你说的那个”。每段固定开头与分支规则，由 Agent 按规则扮演用户；开发 3—4 段用于校准，保留 4—6 段只用于最终比较，具体数目在执行前冻结。E1—E8 作为机制与边界覆盖，可与这些情景合用输入，但通过／失败单独判定，不并入朋友感评分。

每类至少有一个可复现情景；固定输入、时间、来源样本、分支规则与预期证据。开发与保留情景分开；已经讨论的 Fisher 例外只能作开发样例，不能再当未见保留题。正常与失败工具路径先用离线固定证据覆盖，真实模型／语音用于验证接线和体验。实际样本量及调用分配在执行前依现有预算冻结，无法覆盖时交回缺证据项，不追加无限验证。

另以离线工程回归检查五类边界：用户要求不保存时所有新增记录均不落盘；跨身份不能读取记忆／结果或接收卡片；恶意页面指令不能扩权，不安全 URL／私网地址及 API 跳转被拒绝，供应商 Fetch 的不可见转取边界如实标注；累计请求／费用／识别额度耗尽时停止对应能力且不转账本绕开；状态和来源事件不会进入 TTS 或被当成已交付对白。每项保留输入、预期和观察结果，不要求额外真人标注或收费模型调用。

### 判分与通过条件

主判断为成对比较：同一情景的 Angeleno 与同料助手两段，判“哪段更像在问一个 LA 朋友”，以上表特征标注理由，可判相当或无法判断。关键事实与边界单列通过／失败，不进入偏好计数。Jo 以第一人称谈生活，评判者通常能认出哪一臂，报告说明这一点，不声称盲评。先用开发样例校准，不能由未校准模型评委代替 Owner：Owner 对 3 对开发锚例给出判断与理由完成一次校准，之后由 Agent 按该口径评分并在报告中注明评分者；可另用不同模型作第二评分以暴露偏差。最终接受仍以 Owner 真实语音试用为准。

以下工程接受标准随 Spec v5 确认；具体案例、评分锚点和比较条件在执行前冻结：

- E3—E8 中涉及来源、日期、权限、取消、交付和事实来源的关键边界全部通过；明确失败不能被平均分抵消，证据不足不能算通过。
- 保留情景中多数判为 Angeleno 更像朋友，理由落在上表特征且可从对话中指认；关键事实不比同料助手差。不能只用“多调用了工具”或挑一条漂亮回复证明。
- 人物、理解和承接无未处理的明显退化；已有角色材料、模型与固定测试声线在比较中保持受控。
- 正常播完、查询插话／改条件、转题、挂断重拨及浏览器设备链路取得实际证据，响应时间按第5节口径报告。
- 最多两轮 Owner 真实语音试用，整体体验获得认可；两轮后未达标，交回可保留结果、缺口与缩范围建议，不自行开启第三轮优化。

### 交付与后续反馈

交付可理解、可核对的 GitHub 作品：源码、可分享的人物与地方资料、来源说明、现有 GPU／服务条件下的复现步骤、真实短 Demo、比较报告、负面案例与限制。运行说明必须与候选一致，不把本轮扩成托管体验站或普通电脑一键部署。

公开前检查人物、声音及其他素材来源与分发授权；测试声线选择不自动授予声音原件或生成物公开分发。账号、原始私聊、数据库、凭据、原始日志不进入公开材料。合并与公开发布沿既有授权另行处理。

本轮不做线上监控。Owner 试用及获准反馈按版本、情景、输入与现象保留最少必要证据；核实后形成回归例，检查量表和数据是否需修正。没有反馈不等于稳定可靠。未完成的实机验证和所有剩余义务由 [Issue #1](https://github.com/OKFin33/Angeleno/issues/1) 跟踪，不隐藏在文档结论里。
